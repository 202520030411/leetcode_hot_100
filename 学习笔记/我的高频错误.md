# 我的高频错误模式（提交前照着查一遍）

前 5 题一共 10 个 bug，归成 5 类。**其中一半是"不报错但答案错"的**，这类最危险 —— 程序跑得好好的，LeetCode 直接判你 Wrong Answer。

---

## ★ 第 1 类：返回值不对（3 次，全部是静默错误）

| 题 | 我写的 | 正确 |
|---|---|---|
| 两数之和 | `return none` | `return []`（Python 空值是大写 `None`；签名 `-> List[int]` 就该返回 list） |
| 两数之和 | `return seen[complem]` | `return [seen[complem], i]`（少了一半答案） |
| 字母异位词 | `return groups` | `return list(groups.values())`（交出去的是整本 dict） |

**自查：写完 `return`，回头看一眼函数签名的 `->` 后面写的是什么类型，对上没有。**

- `-> List[int]` → 必须是 `[1, 2]` 这种
- `-> List[List[str]]` → 必须是 `[["a"],["b"]]` 这种
- `-> int` → 必须是一个数
- `-> None` → **不要 return**，直接改参数

---

## ★ 第 2 类：死循环 —— while 条件里的变量没更新（2 次）

| 题 | 我写的 | 正确 |
|---|---|---|
| 最长连续序列 | `while x+1 in num_set:` 里写 `cur = x+1` | `while cur+1 in num_set:` 里写 `cur += 1` |
| 盛水容器 | `height[left] += 1` | `left += 1` |

> **铁律：`while` 条件里用到的变量，循环体内必须改变它。**

**自查：写完 while，在循环体里用手指找条件里那个变量名，它必须单独出现在某个赋值的左边。**
`height[left] += 1` 改的是数组内容，**不算**改 `left`。

**症状**：LeetCode 报 `Time Limit Exceeded` (TLE)。见到 TLE 先查死循环，再查复杂度。

---

## ★ 第 3 类：下标 ≠ 值（1 次，但这是最容易反复犯的）

```
height = [ 1,  8,  6,  2,  5]
下标:      0   1   2   3   4
           ↑
         left = 0          ← 位置编号（第几个）
         height[left] = 1  ← 那个位置上的值
```

我写了 `min(left, right)`，比较的是**位置编号 0 和 8**，而不是高度 1 和 7。

**自查：每看到一个方括号 `x[i]`，问自己"我这一步要的是位置还是值"。**
- 要**位置**（返回下标、移动指针、算宽度）→ 用 `i` 本身
- 要**值**（比较大小、求和、判断）→ 用 `x[i]`

---

## 第 4 类：range 的边界（1 次，静默错误）

`for j in range(i, n)` 写成了包含 `j == i` 的情况 → `[3,2,4]` 返回 `[0,0]`。
应该是 `range(i + 1, n)`。

**记住：`range(a, b)` 是左闭右开 —— 包含 a，不包含 b。**
- `range(4)` → 0,1,2,3
- `range(2, 6)` → 2,3,4,5
- 最后一个合法下标是 `len(nums) - 1`

---

## 第 5 类：容器操作方法用错（1 次）

`seen.add((num, i))` → dict 没有 `.add()`，那是 set 的。

| 操作 | set | dict |
|---|---|---|
| 新建空的 | `s = set()` | `d = {}` |
| 放进去 | `s.add(x)` | `d[key] = value` |
| 问在不在 | `x in s` | `key in d` |
| 取出来 | **做不到** | `d[key]` |
| 删掉 | `s.remove(x)` | `del d[key]` |

**决策：只问"在不在" → set；还要拿附带信息（下标/次数/成员） → dict。**

## ★ 第 6 类：答案对但超时（复习时暴露的盲区）

前 5 类查的都是**正确性**。这一类**本地测试全绿，提交才挂 TLE** —— 现有清单查不出来。

**典型例子**（最长连续序列漏掉剪枝）：

```python
for x in num_set:
    # 漏了 if x - 1 in num_set: continue
    cur, length = x, 1
    while cur + 1 in num_set:
        cur += 1; length += 1
```

答案永远正确，但 `[1,2,...,n]` 这种数据会把同一条链反复数：

| n | 步数 | 加剪枝后 |
|---|---|---|
| 10,000 | 49,995,000 | 9,999 |
| 100,000 | 4,999,950,000（约 50 秒） | 100,000 |

**自查方法：写完代码先手算复杂度，和约束对照。**

```
数嵌套层数 → 估出 O(?)  →  查约束表  →  不达标就回去想剪枝
```

- 一层 `for` → O(n)
- `for` 里套 `while`，while 最坏走 n 步 → O(n²)
- **但如果内层"所有轮加起来"总共只走 n 步 → 仍是 O(n)**
  （最长连续序列的剪枝就是靠这个：每个数只在它那条链上被数一次）

## 零碎的（拼写、缩进）

- `traget` → `target`。变量名拼错 → `NameError: name 'xxx' is not defined`
- 缩进 9 格 → `IndentationError: unindent does not match any outer indentation level`
  **每层固定 4 个空格，永远别用 Tab。**

# 提交前自查清单

```
□ 1. return 的类型和函数签名的 -> 对得上吗？
□ 2. 每个 while 的条件变量，循环体里真的被改了吗？
□ 3. 每个 x[i]：我这步要的是位置还是值？
□ 4. range 的起止对吗？j 该从 i 还是 i+1 开始？
□ 5. 题目给的示例全部手动跑一遍 —— 尤其那个看起来"多余"的例子
      （[3,3]、[""] 这种都是出题人专门用来杀错误写法的）
□ 6. 手算复杂度，和约束对照 —— 答案对不代表能过
```

第 5 条最重要。**看起来多余的示例，一定是陷阱。**
