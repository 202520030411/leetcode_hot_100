# 03 最长连续序列（Longest Consecutive Sequence）

> 哈希 · 中等 · https://leetcode.cn/problems/longest-consecutive-sequence/

## 核心思路一句话

**装进 set 后，只从"链头"出发往右一路数到断，取最长的那条。**

## 关键洞察一：换视角，别拼碎片

我一开始想的是"先找出所有相差 1 的数对，再拼成链" —— **卡在"怎么拼接"上。**

> **当一个思路卡在"拼接"上，通常说明视角选错了。**

正确视角：拿着一个数，反复问"下一个在不在"，链是一步步**长出来**的，不是拼出来的。
人眼看 `[100,4,200,1,3,2]` 找出 1,2,3,4 时，用的就是这个方法。

核心操作只有一个：**"x+1 在不在这堆数里？"** → 用 `set`，O(1)。
`set(nums)` 一行同时完成装入和去重（题目说重复不算长度，白送）。

## 关键洞察二：只从链头出发（本题的全部技巧）

若对每个数都往右数一遍，`[1,2,3,4,5]` 要走 5+4+3+2+1 = 15 步，还是 O(n²)。

| 从哪出发 | 数出来 | 长度 |
|---|---|---|
| **1** | 1,2,3,4,5 | **5** ← 唯一有用的 |
| 2 | 2,3,4,5 | 4（被上面包含，白跑） |
| 3 | 3,4,5 | 3（白跑） |

**只有链头值得出发**，从链中间出发永远只得到一个更短的、被包含的答案。

**怎么认链头：它左边那个数不存在。**

```python
if x - 1 not in num_set:      # 左边没人 → 我是链头 → 才开始数
```

加上这一行后，**每个数只会在它所属的那条链上被数一次**，所有链长之和 = n → **O(n)**。

## 我踩过的坑

| 我写的 | 正确 | 后果 |
|---|---|---|
| `while x+1 in num_set:` 里 `cur = x+1` | `while cur+1 in num_set:` 里 `cur += 1` | **死循环**：`x` 是外层 for 的变量，while 里从不改变 → 条件永远为 True |

死循环的样子（`x=1` 固定不动）：
```
轮1  x+1=2 in set? True   cur=2  length=2
轮2  x+1=2 in set? True   cur=2  length=3
轮3  x+1=2 in set? True   cur=2  length=4    ... 永不停止
```

> **`while` 的铁律：循环条件里用到的变量，循环体内必须改变它。**
> 写完 `while` 立刻检查这一条。

**LeetCode 上的表现是 `Time Limit Exceeded` (TLE)**，网站不会告诉你死循环了。
见到 TLE 先查两件事：① 有没有死循环 ② 复杂度是否超标。

## 正确代码

```python
from typing import List

class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        num_set = set(nums)                    # 去重 + O(1) 查询
        longest = 0
        for x in num_set:                      # 遍历 set 比遍历 nums 快（已去重）
            if x - 1 in num_set:
                continue                       # 不是链头，跳过
            cur, length = x, 1
            while cur + 1 in num_set:
                cur += 1
                length += 1
            longest = max(longest, length)     # 打擂台
        return longest
```

**空数组天然处理**：`nums=[]` 时 set 为空，for 一轮不进，返回 0，不用特判。

## 复杂度

时间 **O(n)**，空间 **O(n)**。

## 面试怎么说

"先把数组放进 set 去重，这样查任意数是 O(1)。然后只对『链头』（即 `x-1` 不在 set 里的数）向右延伸。
这个剪枝保证每个数只被访问一次，所以整体是 O(n) 而不是 O(n²)。"
