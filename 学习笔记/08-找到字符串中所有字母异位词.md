# 08 找到字符串中所有字母异位词（Find All Anagrams in a String）

> 滑动窗口（固定长度）· 中等 · https://leetcode.cn/problems/find-all-anagrams-in-a-string/
> 🎞 **交互式可视化**（切到第二个标签页「固定窗口」）：https://claude.ai/artifact/HcKXvy47p6BAAizuK1549L

## 核心思路一句话

**窗口宽度固定为 `len(p)`，每往右挪一格就「放进一个新字符、拿出最旧的字符」，然后比较窗口的字符计数和 `p` 的字符计数是否相等。**

## 洞察一：判断异位词 = 比较字符计数

异位词 = 用了哪些字母、各几个完全相同。

```
"cba" 的计数: a:1, b:1, c:1
"abc" 的计数: a:1, b:1, c:1   →  相同，是异位词 ✅
```

**为什么必须记数量，不能只记「有没有」？**
`"aab"` 和 `"abb"` 用的字母完全相同（都是 a 和 b），但不是异位词 —— 数量不同。
所以这题用 `Counter` 而不是上一题的 `set`。

## 洞察二：窗口长度固定 → 不需要 while 收缩

`p` 长 3，那只有长度恰好为 3 的子串才可能是异位词。窗口永远 3 格宽。

```
k = 3
right=2:  [c  b  a] e  b  a  b  a  c  d      窗口满了，比一次
right=3:   c [b  a  e] b  a  b  a  c  d      吞 'e'，吐 'c'
right=4:   c  b [a  e  b] a  b  a  c  d      吞 'b'，吐 'b'
```

**L 和 R 像一把 3 格宽的尺子整体平移**，距离不变 —— 和上一题（窗口会伸缩）形成对比。
这是滑动窗口的两种形态。

## ★ 我当初的卡点：`win` 是干什么的

```python
need = Counter(p)     # 清单：p 要求「1个a、1个b、1个c」  ← 固定不变
win  = Counter()      # 篮子：窗口里现在装着什么          ← 一直在变
```

**把 `need` 想成购物清单，`win` 想成篮子。** 窗口每右移一格，就是「往篮子放进一个新的、同时拿出最旧的」，然后看篮子和清单是否完全对得上。

`win` 和上一题的 `window = set()` 是**同一个角色** —— 都是"窗口里现在有什么"的记录，区别只在记多细：

| | 07 无重复字符 | 08 本题 |
|---|---|---|
| 用什么 | `set` | `Counter` |
| 记什么 | **有没有**这个字符 | 这个字符**有几个** |

## ★★ 关键：win 不是算出来的，是改出来的

**这是整个滑动窗口模式省时间的全部秘密。**

窗口往右挪一格，**只有两个字符发生变化**：右边进来一个、左边出去一个。
中间那些字符一个都没动，它们的计数凭什么要重算？

```
窗口 "cba" → "bae"
      c 走了、e 来了，b 和 a 原地不动
      → 账本只需要 c 减 1、e 加 1
```

**实测对比**（s 长 10、p 长 3）：

| 做法 | 改动账本次数 | 复杂度 |
|---|---|---|
| 每个起点都重新数一遍 | 24 | O(n·k) |
| 账本增量只改两处 | 17 | **O(n)** |

s 长 30000、p 长 1000 时：**29,001,000 次 vs 60,000 次，差 480 倍。**

> 顺带：第 02 题判断异位词用「排序后比较」，这题为什么换成计数？
> 因为窗口挪一格如果要重新排序是 O(k log k)，比重新数一遍还慢。
> **计数能增量改，排序不能。**

## 两个下标，本题唯一的坑

**① 吐掉哪一格？`s[right - k]`**

```
k=3，right 走到 3，刚吞了 s[3]：
    s[0]   s[1]   s[2]   s[3]
     ↑                     ↑
  right-k=0             right=3
  刚出界的那格           新吞进的
现在窗口 4 格（超 1 格）→ 吐掉 s[0]
```

**② 起始下标是 `right - k + 1`，不是 `right - k`**

```
窗口 = 从 right-k+1 到 right，共 k 格
right=2, k=3  →  窗口 [0,1,2]，起始 = 2-3+1 = 0  ✅
right=8, k=3  →  窗口 [6,7,8]，起始 = 8-3+1 = 6  ✅
```

**`right-k` 是「刚出界的那格」，`right-k+1` 是「窗口第一格」，差 1，别混。**

**③ 为什么条件是 `if right >= k`？**

吞完后窗口里有 `right+1` 个字符，超过 `k` 就要吐 → `right+1 > k` → `right >= k`。

```
right=0  吞了1个       没满
right=2  吞了3个 = k    刚好满，不用吐
right=3  吞了4个 > k    要吐 ← 从这里开始成立
```

## Counter 速查

```python
from collections import Counter

Counter("abc")      # {'a':1,'b':1,'c':1}  —— 就是个 dict，键是字符，值是出现次数
Counter("aab")      # {'a':2,'b':1}
Counter()           # 空的

c = Counter()
c['x'] += 1         # ★ 查不存在的键不报错，自动当 0（普通 dict 会 KeyError）

Counter("abc") == Counter("cba")        # True  ← 判断异位词就这一句
Counter({'a':1,'c':0}) == Counter({'a':1})   # True  ← ★ 比较时忽略计数为 0 的项
```

**第二条性质很重要**：吐掉字符后计数可能变成 0，但不用专门 `del` 删键，比较照样正确。

## 完整代码

```python
from collections import Counter
from typing import List

class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        k = len(p)
        need = Counter(p)              # 清单：固定不变
        win = Counter()                # 篮子：窗口里现在装着什么
        res = []
        for right in range(len(s)):
            win[s[right]] += 1         # 放进篮子
            if right >= k:
                win[s[right - k]] -= 1 # 窗口超宽了，拿出最旧的
            if win == need:            # 篮子和清单对得上？
                res.append(right - k + 1)
        return res
```

## 复杂度

时间 **O(n)** —— 每个字符进出各一次；`win == need` 要比对两个账本，但最多 26 个键（只含小写字母），固定开销不随 n 变。
空间 **O(26) = O(1)**。

## 面试怎么说

"固定长度的滑动窗口。`need` 是 `p` 的字符计数，`win` 是窗口的字符计数，
窗口每右移一格就增量更新两个计数（进一个、出一个），然后比较两个计数是否相等。
时间 O(n)，空间 O(26)。关键是计数能增量维护，不用对每个位置重新统计。"
