# 14 搜索插入位置（Search Insert Position）· 二分查找

> 二分查找 · 简单 · **二分的基本功，边界全在这题里** · https://leetcode.cn/problems/search-insert-position/
> 🎞 **交互式可视化**：https://claude.ai/artifact/VeKz9WteNdXfc2C8mzwvgu

## 二分查找是什么

**前提：数组必须有序。** 看中间那个数，和目标比一下，就能断定目标在左半边还是右半边 —— 另一半**整个排除**，连看都不用看。

```
在 [1,3,5,7,9,11,13] 里找 11：
[1, 3, 5, 7, 9, 11, 13]      中间是 7，7 < 11  →  目标在右边，左半边全排除
             ↑ mid
             [9, 11, 13]     中间是 11，命中 ✅
                  ↑ mid
```

**为什么 O(log n)**：每次砍一半，n 个元素最多砍 log₂n 次。

| n | 最多几次 |
|---|---|
| 1,000 | 10 |
| 1,000,000 | 20 |
| 10^9 | 30 |

**约束里 n 到 10^9 几乎总是在喊二分。**

### 触发信号

```
"有序数组" / "排好序"            →  二分（或相向双指针）
"请使用 O(log n) 的算法"         →  二分，题目直接点名
"找某个值 / 找第一个满足X的位置"   →  二分
n 到 10^9 / 10^18              →  二分或数学推导
```

**和双指针的区别**：都要求有序，但**双指针是两端往中间夹、每次挪一格；二分是看中间、直接砍掉一半**。二分快得多（log n vs n），但只能"找单个位置"，不能"找配对"。

## ★★ 核心：left 和 right 的定义（这题的全部）

整个过程中这两句话**始终成立**：

```
left  的含义：它左边的元素，全都 < target
right 的含义：它右边的元素，全都 > target
```

**为什么始终成立？** 因为那两行代码刻意维持它：

```python
nums[mid] < target  →  left = mid + 1
    数组有序，nums[mid] < target 意味着 nums[0..mid] 全 < target
    新 left = mid+1，它左边（0..mid）确实全 < target  ✅

nums[mid] > target  →  right = mid - 1
    nums[mid] > target 意味着 nums[mid..末尾] 全 > target
    新 right = mid-1，它右边（mid..末尾）确实全 > target  ✅
```

（这种「从头到尾都成立的条件」CS 里叫**循环不变量**，名字不重要。
重要的是：**写二分时想清楚 left/right 各自代表什么含义，边界就不会错 —— 这比背模板可靠。**）

### 所以 left 是一条分界线

```
已确定全部 < target  │  已确定全部 > target
                     ↑ 这条线就是 target 该插进去的地方
```

```
初始:   [ ?  ?  ?  ?  ?  ?  ? ]        全部不确定
         L                    R
中间:   [ <  <  ?  ?  ?  >  > ]        两头各确定了一些
               L     R
               └─不确定─┘
结束:   [ <  <  <  <  >  >  > ]        不确定区为空
                  R  L
                     ↑ left 就是分界点
```

**「交错」= `left == right + 1`，即 R 在 L 左边一格，它们之间一个元素都没有。**
此时左边全小、右边全大，分界线唯一确定 → `return left`。

**为什么必然交错不会停在重合？** 循环条件是 `left <= right`，相等时还会跑一轮（检查最后那个元素），跑完必然错开。

### 实测验证（每步两个条件都成立）

```
nums = [1,3,5,7,9,11,13],  target = 10

初始:  left=0 左边 [] 全<10 ✅          right=6 右边 [] 全>10 ✅
轮1:   mid=3, 7<10  → left=4
       left=4 左边 [1,3,5,7] 全<10 ✅   right=6 右边 [] ✅
轮2:   mid=5, 11>10 → right=4
       left=4 左边 [1,3,5,7] ✅         right=4 右边 [11,13] 全>10 ✅
轮3:   mid=4, 9<10  → left=5
       left=5 左边 [1,3,5,7,9] ✅       right=4 右边 [11,13] ✅

退出: left=5 > right=4
      下标 0~4 全 < 10，下标 5~6 全 > 10  →  return 5
```

## ★ 二分的本质

**不是在「找 target」，而是在「把分界线逼出来」。**

```
找到 target  =  分界线正好落在一个和 target 相等的元素上（提前 return mid）
没找到       =  分界线落在两个元素之间，那个缝隙就是插入位置
```

## ★ 两种区间写法，别混

**写二分前先问：`right` 这个下标算不算在搜索范围内？**

| | **闭区间** `[left, right]`（推荐） | **左闭右开** `[left, right)` |
|---|---|---|
| `right` 含义 | **包含**在范围内 | **不包含**，是"末尾之后一格" |
| 初始 `right` | `len(nums) - 1` | `len(nums)` |
| 循环条件 | `left <= right` | `left < right` |
| 太小时 | `left = mid + 1` | `left = mid + 1` |
| 太大时 | `right = mid - 1` | **`right = mid`**（不减 1！） |

**左闭右开时 `right = mid` 为什么不减 1？** 因为 `right` 本来就不包含在范围内，设成 `mid` 就自动排除了 `mid`。
闭区间里 `right` 是包含的，所以必须 `-1` 才能排除。

**两种都对，混着写必出 bug（典型是死循环）。固定用闭区间那一套，三行记死：**

```
right = len(nums) - 1
while left <= right
left = mid + 1  /  right = mid - 1
```

## ★ // 是什么，除不尽怎么办（我问过这个）

**`//` 是整数除法：算完把小数部分直接丢掉（向下取整）。**

```python
6 // 2     # 3      除得尽
7 // 2     # 3      除不尽 → 3.5 丢掉小数 → 3
7 /  2     # 3.5    普通除法
```

**必须用 `//` 的原因：下标不能是小数。**
`nums[7 / 2]` → `TypeError: list indices must be integers or slices, not float`

### 「mid 偏左」要紧吗？对我们这套写法——不要紧

```
区间         元素个数   mid   左边几个  右边几个
[0, 1]         2       0       0       1     ← 偶数个，mid 偏左
[0, 2]         3       1       1       1     ← 奇数个，正中
[0, 3]         4       1       1       2     ← 偶数个，偏左
```

**不管偏哪边，`mid` 都被 `±1` 排除出去了 → 区间每轮严格变小 → 必然收敛。**

```
n=10 的收敛过程：元素个数 10 → 5 → 2 → 1 → 0，共 4 轮
log₂10 ≈ 3.3 向上取整 4 ✅
```

### ★ 但有一种写法会在意（所以要固定写法）

| 收缩写法 | 区间会缩小吗 | mid 取整方向 |
|---|---|---|
| **`left = mid+1` / `right = mid-1`**（两边都排除 mid） | **一定缩小** | **无所谓** ✅ |
| `left = mid`（保留 mid） | 可能不缩小 | 必须**向上**取整 `(l+r+1)//2` |
| `right = mid`（保留 mid） | 可能不缩小 | 必须向下取整 |

**实测 `left = mid` 配向下取整的死循环：**

```
区间 [0,1] 要往右收缩，写成 left = mid：
   第1轮: mid=(0+1)//2=0 → left=mid=0     区间没变！
   第2轮: mid=(0+1)//2=0 → left=mid=0     ... 永远不停
改成向上取整 mid=(0+1+1)//2=1 → left=1，正常退出 ✅
```

> **「固定用 ±1 那套」的好处：不用想取整方向。** 混用两套体系必死（典型是死循环）。

> ⚠ **但 ±1 不是万能的 —— 见 [17 旋转数组找最小](./17-旋转数组找最小.md)。**
> 当 **mid 本身可能就是答案**时（找边界 / 找极值），必须用 `right = mid` 保留它，配 `while left < right`。
> 那是 **B 套**写法，同样自洽。两套的选择标准：**mid 能不能排除。**

（Python 冷知识：`//` 对负数向下取整，`-7 // 2 = -4` 不是 `-3`。二分里 left/right 非负所以碰不到。）

## 四个必须记死的细节

**① `//` 是整数除法（向下取整）**

```python
7 // 2     # 3     ← 商取整
7 / 2      # 3.5   ← 下标不能是小数，用 / 会报 TypeError: list indices must be integers
```

**② `left = mid + 1` / `right = mid - 1` 的 ±1 不能省**
`nums[mid]` 已经比过、确定不是答案，必须排除出去。写成 `left = mid` → 范围不缩小 → **死循环**。

**③ `while left <= right` 是 `<=` 不是 `<`**
`left == right` 时范围里还剩一个元素没检查，用 `<` 会漏掉它。

**④ 最后 `return left` 不是 `return -1`**
这题要插入位置。如果题目只要"找不到返回 -1"，那就 `return -1`。

## 完整代码

```python
from typing import List

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1          # 闭区间，两端都包含
        while left <= right:                    # 范围非空就继续
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid                      # 命中
            elif nums[mid] < target:
                left = mid + 1                  # 太小 → 答案在右边
            else:
                right = mid - 1                 # 太大 → 答案在左边
        return left                             # 交错了，left 就是分界线
```

## 复杂度

时间 **O(log n)**，空间 **O(1)**。

## 面试加分点

`mid = (left + right) // 2` 在 Python 里没问题，但 **C++/Java 里 `left + right` 可能整数溢出**，
那些语言写 `mid = left + (right - left) // 2`。Python 整数无上限不用担心，但知道这回事能答上追问。

## 面试怎么说

"标准二分。用闭区间 `[left, right]`，循环条件 `left <= right`。
每轮取 `mid`，命中就返回；`nums[mid] < target` 说明答案在右边，`left = mid + 1`；反之 `right = mid - 1`。
整个过程保持『left 左边全小、right 右边全大』这个不变量，
所以循环退出时 `left` 恰好是插入位置。时间 O(log n)，空间 O(1)。"
