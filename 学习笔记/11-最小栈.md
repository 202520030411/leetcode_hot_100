# 11 最小栈（Min Stack）

> 栈 · 设计题 · 中等 · **国内面试高频** · https://leetcode.cn/problems/min-stack/
> 🎞 **交互式可视化**（双栈并排 + 单变量做法失效对照）：https://claude.ai/artifact/FLNCT4EMT9zA3BTCf7fRG7

## 核心思路一句话

**再开一个栈和主栈同步升降，它的第 i 层记「主栈前 i 层的最小值」—— 一串快照。`getMin()` 就是看它的栈顶。**

## 这是我的第一道设计题

前十题都是「写一个函数」，这题是「实现一个类」—— 它要**在多次调用之间记住状态**。

```
push(-2); push(0); push(-3)
getMin()  →  -3
pop()
top()     →  0
getMin()  →  -2      ← 最小值变了，而且不能重算
```

## ★ class / __init__ / self（我在 PyTorch 里写过同样的东西）

```python
class MyModel(nn.Module):              class MinStack:
    def __init__(self):                    def __init__(self):
        super().__init__()                     self.stack = []
        self.linear = nn.Linear(10, 5)         self.min_stack = []

    def forward(self, x):                  def push(self, val):
        return self.linear(x)                  self.stack.append(val)
```

| PyTorch 里 | 这题里 | 含义 |
|---|---|---|
| `__init__` | `__init__` | **造对象时自动跑一次**的初始化，准备要长期保存的东西 |
| `self.linear` | `self.stack` | **挂在对象身上**的东西，所有方法都能用，调用之间一直存在 |
| `self` | `self` | 「**这个对象自己**」。写在参数第一位，调用时不用传 |
| `forward(x)` | `push(val)` | 对象的方法，外面调用的入口 |

```python
def push(self, val):
    stack = []              # ❌ 只活在这次调用里，函数结束就没了
    self.stack.append(val)  # ✅ 挂在对象上，下次调用还在
```

**为什么前十题的 `class Solution` 不需要 `__init__`**：那些题只是「输入进来、算一下、返回」，不需要在调用之间记住任何东西。

## ★★ 核心难点：为什么不能只记一个 min 变量

**朴素做法一**：`getMin()` 时扫一遍整个栈 → O(n)，题目要 O(1) ❌

**朴素做法二**：记一个变量 `self.min`，push 时更新 → **pop 的时候崩**：

```
push(3)   →  栈 [3]      min = 3
push(1)   →  栈 [3,1]    min = 1
getMin()  →  1   ✅
pop()     →  栈 [3]      min 还是 1  ❌ 正确答案应该是 3
                ↑ 最小值被弹走了，但不知道「第二小」是谁
```

> **根本问题：`min` 是一个会被破坏的状态，`pop` 破坏了它，而没有备份。** 要恢复就得重新扫 → 又回到 O(n)。

## 解法：给每一层留一张快照

```
      主栈          min 栈
顶    -3     ←→      -3      ← 到这一层为止，最小是 -3
       0     ←→      -2      ← 到这一层为止，最小是 -2
底    -2     ←→      -2      ← 到这一层为止，最小是 -2
```

- **`push(val)`**：主栈放 `val`；min 栈放 **`min(val, min栈栈顶)`**
- **`pop()`**：两个栈**一起**弹
- **`getMin()`**：返回 **min 栈的栈顶**

**pop 之后为什么自动正确？** 上一层的快照一直存着 —— 弹掉顶层，下面那层露出来，它记的正是「剩下这些元素的最小值」。**用 O(n) 空间换「可以回退」的能力。**

**注意 min 栈要「每次 push 都放一个」，不能「只在变小时才放」** —— 后者碰到重复的最小值会出错（`push 2, push 2, pop, getMin` 应该还是 2）。

## 我踩过的坑

| 我写的 | 正确 | 报错 |
|---|---|---|
| `min(val, min_stack[-1])` | `min(val, self.min_stack[-1])` | `NameError: name 'min_stack' is not defined` |

**`min_stack` 和 `self.min_stack` 是两个完全不同的东西。** 不写 `self.`，Python 就去找一个叫 `min_stack` 的普通变量，找不到就报错。

同一个坑在 PyTorch 里：

```python
def forward(self, x):
    return linear(x)        # ❌ NameError
    return self.linear(x)   # ✅
```

**规则：凡是在 `__init__` 里用 `self.xxx = ...` 建的东西，以后每次用都必须写 `self.`**

| 写法 | 是什么 | 活多久 |
|---|---|---|
| `val` | 方法的**参数** | 这次调用结束就没了 |
| `cur_min = ...` | 方法里的**临时变量** | 这次调用结束就没了 |
| `self.min_stack` | 挂在**对象**上的属性 | 对象活着就一直在 |

**判断：这东西需要在「下次调用」时还存在吗？** 需要 → `self.`

## 完整代码

```python
class MinStack:
    def __init__(self):
        self.stack = []                    # 主栈：实际存的值
        self.min_stack = []                # 每层 = 到这层为止的最小值

    def push(self, val: int) -> None:
        self.stack.append(val)
        if not self.min_stack:
            self.min_stack.append(val)                              # 第一个元素
        else:
            self.min_stack.append(min(val, self.min_stack[-1]))     # 和旧最小值比

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()               # ★ 两个栈必须同步弹，最容易漏这行

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]          # 一步到位，O(1)
```

**更紧凑的 push（两种面试都行）：**

```python
    def push(self, val: int) -> None:
        self.stack.append(val)
        self.min_stack.append(min(val, self.min_stack[-1] if self.min_stack else val))
```

## 复杂度

四个操作**全是 O(1)**（都只碰栈顶）。空间 **O(n)**。

## 面试怎么说

"用一个辅助栈 `min_stack` 和主栈同步升降，它的每一层记录『主栈到这一层为止的最小值』。
`push` 时放 `min(val, 辅助栈顶)`，`pop` 时两个栈一起弹，`getMin` 直接返回辅助栈顶。
四个操作都是 O(1)，代价是 O(n) 额外空间。
关键是：只用一个 `min` 变量不行，弹掉最小值后它就失效了；辅助栈保留每一层快照，天然支持回退。"

**追问「能不能省空间」**：可以改成只在 `val <= 当前最小值` 时才往辅助栈 push，`pop` 时若弹出的值等于辅助栈顶就一起弹。
**必须是 `<=` 不是 `<`**，否则重复的最小值会出错。第一版先写同步双栈，清楚不易错。
