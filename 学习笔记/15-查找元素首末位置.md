# 15 在排序数组中查找元素的第一个和最后一个位置

> 二分查找变体 · 中等 · https://leetcode.cn/problems/find-first-and-last-position-of-element-in-sorted-array/
> 🎞 **交互式可视化**（两次 lower_bound）：https://claude.ai/artifact/MWfqBjgEGAGLTZAywgrYEr

## 核心思路一句话

**手写一个 `lower_bound`（第一个 >= x 的位置），调两次：首位置 = `lower_bound(target)`，末位置 = `lower_bound(target+1) - 1`。**

## 上一题的模板为什么不够

```
nums = [5, 7, 7, 8, 8, 10]
下标:   0  1  2  3  4   5
                  └──┘  target=8 占了两格
```

第 14 题一旦 `nums[mid] == target` 就 `return mid`，但 **mid 可能落在这一段的任何位置** —— 它只回答了「8 在不在」，没回答「从哪开始、到哪结束」。

## ★★ 关键改造：找到了也别停

```python
def lower_bound(x):
    """第一个 >= x 的位置（可能等于 len(nums)）"""
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] >= x:
            right = mid - 1      # ★ 这个 mid 可能是答案，但左边也许还有更早的 → 继续往左压
        else:
            left = mid + 1
    return left
```

**只改两处**：条件从 `== / <` 变成 `>=`；命中时不 `return` 而是 `right = mid - 1`。

> **「找第一个满足条件的位置」的通用技巧：找到候选不要停，继续往那个方向压，直到压不动。**

分界线的说法：

```
全部 < x   │   全部 >= x
           ↑ 返回的 left
```

（标准名字叫 `lower_bound`，Python 标准库是 `bisect.bisect_left`。面试手写。）

## 两次调用

```
第一个 target  =  lower_bound(target)              第一个 >= target 的位置
最后一个 target =  lower_bound(target + 1) - 1      第一个 > target 的位置，退一格
```

```
nums = [5, 7, 7, 8, 8, 10]
下标:   0  1  2  3  4   5
                  └──┘
lower_bound(8) = 3           ← 第一个 >= 8
lower_bound(9) = 5           ← 第一个 >= 9（那个 10）
                 5 - 1 = 4   ← 退一格，正好是最后一个 8 ✅
```

## ★ [-1,-1] 那两行（我问过这个）

`[-1,-1]` 只是**题目规定的「不存在」返回值**（`-1` 不可能是合法下标）。

**为什么需要检查：`lower_bound` 回答的是「该插在哪」，不是「在不在」。** 它永远给你一个位置，哪怕 target 根本不存在。

```python
if first == len(nums) or nums[first] != target:
   ↑ 情况A                ↑ 情况B
    return [-1, -1]
```

| | 条件 | 含义 | 例子 |
|---|---|---|---|
| **情况 A** | `first == len(nums)` | 落点跑到数组外，target 比所有元素都大 | `target=20` → `first=6=len` |
| **情况 B** | `nums[first] != target` | 落点在数组内，但那格的值不是 target | `target=6` → `first=1`，`nums[1]=7≠6` |

**为什么「落点的值不是 target」就能断定整个数组都没有？**

```
落点左边：  全部 < target      → 左边不可能有
落点及右边：全部 >= target，而落点的值已经 > target（因为 != 且 >=）
            数组有序，右边只会更大  → 右边也不可能有
两边都排除 → 不存在
```

**实测表：**

```
nums = [5,7,7,8,8,10]
target   lower_bound   落点上的值     结论
5        0             5             存在，首位置 0
6        1             7             情况B：7 ≠ 6 → [-1,-1]
8        3             8             存在，首位置 3
9        5             10            情况B：10 ≠ 9 → [-1,-1]
20       6             （数组外）      情况A → [-1,-1]
0        0             5             情况B：5 ≠ 0 → [-1,-1]
```

## ★★ 第三次遇到「先查边界，再查内容」

```python
# 06 三数之和
if i > 0 and nums[i] == nums[i-1]:
   ↑ 先确认能取          ↑ 再比较内容

# 10 有效的括号
if not stack or stack[-1] != pairs[ch]:
   ↑ 先确认栈非空        ↑ 再比较内容

# 15 这里
if first == len(nums) or nums[first] != target:
   ↑ 先确认不越界        ↑ 再比较内容
```

**靠 `and` / `or` 的短路**：左边决定了结果，右边根本不会被执行，所以不会越界。
**反过来写一定崩** —— 实测 `target=20` 时先查 `nums[first]` 直接 `IndexError`。

> **以后每次要访问 `x[i]` 之前，先问一句「`i` 一定在范围内吗」。**

## 完整代码

```python
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def lower_bound(x):
            """第一个 >= x 的位置（可能等于 len(nums)）"""
            left, right = 0, len(nums) - 1
            while left <= right:
                mid = (left + right) // 2
                if nums[mid] >= x:
                    right = mid - 1        # 可能是答案，但继续往左找更早的
                else:
                    left = mid + 1
            return left

        first = lower_bound(target)
        if first == len(nums) or nums[first] != target:
            return [-1, -1]                # 两种不存在：越界 / 落点值不对
        last = lower_bound(target + 1) - 1 # 第一个 > target 的位置，退一格
        return [first, last]
```

**`def lower_bound(x):` 写在 `searchRange` 里面** —— 函数里套函数，好处是它能直接用外层的 `nums`，不用当参数传。面试里很常见。

## 复杂度

时间 **O(log n)**（两次二分，`2 log n` 扔掉系数），空间 **O(1)**。

## 面试怎么说

"手写一个 `lower_bound`（第一个 >= x 的位置）。关键是命中时不返回，而是 `right = mid - 1` 继续往左压，
这样才能找到最左边那个。然后第一个位置就是 `lower_bound(target)`，最后一个位置是 `lower_bound(target+1) - 1`。
判断不存在要检查落点是否越界、以及落点的值是否真等于 target。两次二分，O(log n)。"
