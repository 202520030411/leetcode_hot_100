# 17 寻找旋转排序数组中的最小值（Find Minimum in Rotated Sorted Array）

> 二分查找 · 中等 · **概念升级：二分的真正前提是什么** · https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/
> 🎞 **交互式可视化**：https://claude.ai/artifact/4xmeRptEzCw1hpGLQGaGUG

## 核心思路一句话

**拿 `nums[mid]` 和 `nums[right]` 比：mid 比它大就说明 mid 在「大段」，最小值在右边；否则 mid 在「小段」，最小值是 mid 或在它左边。**

## 旋转后的数组长什么样

```
[4, 5, 6, 7, 0, 1, 2]
 └──左段──┘  └─右段─┘
   各自升序      各自升序
        ↑ 断崖：7 掉到 0

★ 左段的每个数都 > 右段的每个数
★ 最小值 = 右段的第一个 = 断崖底部
```

## ★★ 概念升级：二分的真正前提

**不是「全局有序」，而是「能根据 mid 判断答案在哪一半」。**

有序只是让这个判断变容易（比一下大小）。只要有别的办法判断方向，二分照样成立。

**这题的判断办法：**

```
nums[mid] > nums[right]   →  mid 在【左段】（大的那段）
                             最小值一定在 mid 右边  →  left = mid + 1

nums[mid] < nums[right]   →  mid 在【右段】（小的那段）
                             最小值是 mid 本身或在它左边  →  right = mid
```

```
[4, 5, 6, 7, 0, 1, 2]        mid=3(值7)  right=6(值2)
 L        M        R          7 > 2 → mid 在左段 → left = 4

[4, 5, 6, 7, 0, 1, 2]        mid=5(值1)  right=6(值2)
             L  M  R          1 < 2 → mid 在右段 → right = 5
```

**参照物用 `nums[right]` 而不是 `nums[left]`** —— 它跟着 right 变，但每次比较时都是「当前范围最右那个」，足够判断方向。
**而且不需要特判「没旋转」的情况**（`[11,13,15,17]`），同一套代码自然就对。

## ★★★ 这题必须用 B 套写法（修正了我之前的建议）

我之前说「固定用 `±1`，看到 `right = mid` 就跳过」。**那条对第 14/15/16 题成立，对这题不成立。**

**区别一句话：这题的 `mid` 可能就是答案本身。**

```
nums[mid] < nums[right]  →  mid 落在右段，而右段第一个就是最小值
                            mid 自己就可能是那个最小值 → 不能排除！
```

**实测反例：**

```
nums                  真正最小值   right=mid   right=mid-1
[4, 5, 6, 7, 0, 1, 2] 0           0 ✅         0 ✅
[3, 1, 2]             1           1 ✅         3 ❌  ← mid 第一步就落在答案上
对拍 5000 组:                      错 0 次      错 1320 次（26%）
```

`[3,1,2]`：`mid=1`（值 1）就是最小值，`right = mid-1 = 0` 直接把它踢出范围，再也找不回来。

### 两套写法，按「mid 能不能排除」选

| | **A 套**（14/15/16 题） | **B 套**（本题） |
|---|---|---|
| 什么时候用 | 比较后 **mid 确定不是答案** | **mid 可能就是答案** |
| 循环条件 | `while left <= right` | **`while left < right`** |
| 收缩 | 两边都 `±1` | 一边 `right = mid`（保留）、一边 `left = mid + 1` |
| 返回 | `left`（位置）或 `-1` | **`nums[left]`**（退出时 `left == right`） |

**记法：**

```
找「一个确定的值」                      →  A 套（±1）
找「边界 / 极值」，mid 本身可能就是答案    →  B 套（保留 mid）
```

### B 套为什么不死循环

`while left < right` 保证 `left < right`，此时 `mid = (left+right)//2` 一定满足：

```
left <= mid < right        ← mid 严格小于 right（向下取整的功劳）
   ↓                ↓
right = mid  → right 严格变小 ✅
left = mid+1 → left 严格变大 ✅
```

两条路都在缩小范围 → 必然收敛。
**这也说明 B 套必须配向下取整** —— 配向上取整时 `mid` 可能等于 `right`，`right = mid` 就不动了 → 死循环。

## 完整代码

```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        while left < right:                 # B 套：< 不是 <=
            mid = (left + right) // 2
            if nums[mid] > nums[right]:
                left = mid + 1              # mid 在大段，最小值在右边
            else:
                right = mid                 # mid 在小段，可能就是答案 → 保留
        return nums[left]                   # 退出时 left == right，返回【值】
```

**注意返回的是值不是下标** —— 题目要最小元素本身。

## 复杂度

时间 **O(log n)**，空间 **O(1)**。

## 面试怎么说

"虽然数组不是全局有序的，但它由两段升序组成，而且左段每个数都大于右段每个数。
所以拿 `nums[mid]` 和 `nums[right]` 比就能判断 mid 落在哪一段：
大于说明在左段，最小值在右边，`left = mid + 1`；否则在右段，最小值是 mid 或在它左边，`right = mid`。
这里 `right = mid` 不能减 1，因为 mid 自己可能就是最小值。
循环条件用 `left < right`，退出时两者相等，那一格就是答案。O(log n)。"
