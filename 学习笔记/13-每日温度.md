# 13 每日温度（Daily Temperatures）· 单调栈

> 栈 · 中等 · **单调栈入门，解锁三道困难题** · https://leetcode.cn/problems/daily-temperatures/
> 🎞 **交互式可视化**（柱高＝温度，紧凑单屏版）：https://claude.ai/artifact/3FaLibYo2VFBftvBTRVFGD

## 题目在问什么（先搞清这个）

**对每一天，往右找第一个比它高的温度，返回隔了几天；找不到填 0。**

```
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
下标:            0   1   2   3   4   5   6   7
```

| 天 | 温度 | 往右找第一个更高的 | 等了几天 |
|---|---|---|---|
| 0 | 73 | 第 1 天 74 ✅ | `1-0 = 1` |
| 1 | 74 | 第 2 天 75 ✅ | `2-1 = 1` |
| 2 | 75 | 71❌ 69❌ 72❌ **76 ✅** | `6-2 = 4` |
| 3 | 71 | 69❌ **72 ✅** | `5-3 = 2` |
| 4 | 69 | 第 5 天 72 ✅ | `5-4 = 1` |
| 5 | 72 | 第 6 天 76 ✅ | `6-5 = 1` |
| 6 | 76 | 73❌，没更多天了 | **0** |
| 7 | 73 | 后面没天了 | **0** |

`answer = [1,1,4,2,1,1,0,0]`

**`answer` 里存的是天数，不是温度也不是下标。**

> **「右边第一个更大/更小的元素」这个问法就是单调栈的标准触发信号。**

## 暴力解浪费在哪

```
第 2 天(75) 往右扫：71❌ 69❌ 72❌ 76✅     扫 4 格
第 3 天(71) 往右扫：69❌ 72✅               扫 2 格
第 4 天(69) 往右扫：72✅                   扫 1 格
                     ↑ 69 和 72 被反复扫了好几遍
```

**第 5 天那个 72 出现时，它同时就是第 3 天和第 4 天的答案** —— 一次出现本该一次解决两个问题，暴力解却让它们各跑一趟。

## ★ 视角反转（这题的核心）

```
暴力：   每一天主动往右跑，去找自己的答案      →  n 个人各跑一趟
单调栈： 每一天到来时，主动结算前面等它的那些天  →  一次广播，所有等它的人同时知道
```

**让答案来找人，不是人去找答案。**

## ★ 栈里存什么：「还没拿到答案的那些天」

和学过的两种账本对比：

| 模式 | 账本存什么 | 进出规则 |
|---|---|---|
| **哈希表**（01 两数之和） | 历史上**所有**见过的 | **只进不出** |
| **滑动窗口**（07 无重复子串） | 当前窗口里的 | 出窗口就划掉 |
| **单调栈**（本题） | **还没拿到答案的那些** | **拿到答案就扔掉** |

**单调栈更像滑动窗口，不像哈希表** —— 它主动清理，栈不会越来越大。
走到第 6 天时栈里只剩 `[2, 5]`，第 0/1/3/4 天早被弹走了。

**「扔得干净」正是它能 O(1) 判断的原因：**

```
扔掉没用的  →  栈自动单调（从底到顶越来越矮）  →  只看栈顶就够  →  O(1) 判断  →  整体 O(n)
```

如果栈里乱序，每次都得翻一遍栈 → 又回到 O(n²)。

## 操作次数实测

| n | 暴力的比较次数（随机数据） | 单调栈的进出栈次数 |
|---|---|---|
| 8 | 9 | 14 ← **栈反而更多！** |
| 100 | 452 | 195 |
| 1,000 | 10,218 | 1,980 |
| 10,000 | 742,572 | 19,851 |
| 100,000 | 70,634,711 | 198,611 |

**三点：**
1. **小数据上单调栈没优势甚至更慢**（多了进出栈的动作）。优化是为大数据准备的。
2. **单调栈那列几乎正好 2n** —— 每天入栈一次、出栈最多一次，**不管数据长什么样**。
3. 暴力那列是随机数据，不是最坏情况。**温度一路递减时**（`[100,99,98,...]`）每天都要扫到末尾 → `n=10^5` 约 5×10⁹ 次 → TLE。
   **面试算复杂度永远按最坏情况算。**

## ★ 栈里存下标，不是温度

```python
stack.append(i)                      # ✅ 存下标
temperatures[stack[-1]]              # 想要温度？用下标去取（两层方括号）
ans[j] = i - j                       # 答案是天数差，只有下标能算距离
```

`stack[-1]` 取出栈顶存的**下标**，再用它去 `temperatures` 里取**温度**。
这是「下标 vs 值」的升级版，看清两层分别在取什么。

## 我踩过的坑

| 我写的 | 正确 | 报错 |
|---|---|---|
| `temperature[stack[-1]]` | `temperatures[stack[-1]]` | `NameError`（参数名是复数） |

**第二次栽在拼写上**（第一次 `traget`）。
**自查：变量名直接从函数签名那一行复制，别凭记忆敲。**

## 完整代码

```python
from typing import List

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        ans = [0] * n                                      # 默认 0（等不到）
        stack = []                                         # 存还在等的那些天的【下标】
        for i, t in enumerate(temperatures):
            while stack and t > temperatures[stack[-1]]:   # 能结算掉栈顶那天吗
                j = stack.pop()
                ans[j] = i - j                             # 它等了 i-j 天
            stack.append(i)                                # 今天自己入栈开始等
        return ans
```

**`while` 不是 `if`** —— 一个暖和的日子可能一次结算掉好几天。
**条件是严格大于 `>`** —— 温度相等不算「更高」，不结算（`[70,70,70,80]` 前三个会一直堆着）。
**`stack` 非空判断必须在前**，靠 `and` 短路，否则 `stack[-1]` 会 `IndexError`（和第 10 题同一个坑）。

## 复杂度

时间 **O(n)**，空间 **O(n)**。

## 面试怎么说

"单调栈。栈里存还没找到更高温度的那些天的下标，栈内温度从底到顶递减。
每来一天就把栈里所有比它低的日子弹出来结算 `ans[j] = i - j`，然后自己入栈。
每个下标只入栈出栈各一次，所以整体 O(n)。
关键是『让答案来找人』—— 不是每天自己往右扫，而是新的一天到来时一次性结算掉所有等它的天。"

## 这题解锁了什么

**「右边/左边第一个更大/更小的元素」这类问题全都是这个套路**，包括三道之前跳过的困难题：

- **接雨水**（双指针类，也可单调栈）
- **滑动窗口最大值**（单调队列 = 单调栈的双头版本）
- **柱状图中最大的矩形**（单调栈的巅峰）
